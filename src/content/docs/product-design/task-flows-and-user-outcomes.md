# Task flows and user outcomes

A task flow describes the steps and decisions a user takes to reach an outcome. A journey can include a wider sequence across time, channels, people, and systems.

Start with the outcome rather than the current interface. A current workflow can contain accidental steps that should be removed instead of reproduced.

## Model the work

Record the trigger, intended result, important decisions, required information, handoffs, failure paths, and completion condition. Include branches that materially change the experience.

Needs, goals, Jobs to Be Done, user stories, and similar frames can all help describe intent. None is a complete model by itself. Choose the frame that makes the decision clearer and test its assumptions against evidence.

## Find unnecessary steps

A step is not valuable merely because the existing product contains it. Repeated entry, avoidable navigation, redundant confirmation, hidden prerequisites, and unnecessary context changes can increase interaction cost.

Do not optimize only for fewer clicks. A deliberate extra step can improve comprehension, safety, or confidence when consequences are significant.

## Validate the flow

Compare the model with observed behavior, research, support evidence, and usability tests. A diagram created only from team assumptions is a hypothesis.

## Limits

Task flows simplify reality. Users can enter midway, switch devices, pause work, ask another person for help, or pursue several goals at once. Preserve those cases when they affect the design.
