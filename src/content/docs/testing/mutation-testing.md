# Mutation testing

Mutation testing changes production code in small artificial ways and checks whether the existing tests fail.

A changed version is a mutant.

If the test suite still passes, the mutant survives. That result suggests the tests did not observe the changed behavior, although it does not prove the original code is defective.

## Typical mutations

Mutation tools can change behavior such as:

- reversing a boolean condition;
- replacing `<` with `<=`;
- removing a method call;
- changing a constant;
- replacing a returned value;
- removing an update or branch.

Useful mutations should approximate plausible semantic mistakes rather than arbitrary syntax corruption.

## What a mutation score means

A high mutation-kill rate indicates that the tests are sensitive to many changes generated by the mutation model.

It does not prove complete correctness.

The tool can miss defect classes it does not mutate, and tests can kill mutants while still asserting the wrong product contract.

Mutation testing therefore measures test sensitivity, not application quality directly.

## Equivalent mutants

Some mutations do not change observable behavior for the program context.

These equivalent mutants cannot be killed by a correct test and can make the reported score misleading.

Human review or tool heuristics may be needed to distinguish them from genuine coverage gaps.

## Cost

Mutation testing runs many modified program versions and can be expensive on a large test suite.

Use scope controls, incremental mutation, changed-file selection, or scheduled runs when full mutation analysis is too slow for every pull request.

Prioritize critical pure logic where strong tests matter more than a repository-wide score.

## Practical guidance

Use mutation testing when line or branch coverage is high but confidence in assertions is uncertain.

Investigate surviving meaningful mutants as evidence of weak observations or missing cases.

Do not turn one numeric mutation score into a merge target without considering equivalent mutants, cost, and which code actually carries product risk.
